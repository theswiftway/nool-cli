=== nool propose ===
Generate a candidate Knot (interactive wizard mode recommended for beginners)

Usage: nool propose [OPTIONS]

Options:
  -i, --intent <INTENT>              Describe what you're changing (e.g. "fix rate limiting")
  -p, --payload <PAYLOAD>            
  -k, --kind <KIND>                  Knot kind (e.g. fn, test, config, doc). Auto-detected if omitted
      --path <PATH>...               Path(s) to the changed file(s) (space-separated: --path file1 file2 file3)
  -t, --thread <THREAD>              
  -s, --solidify                     Automatically sign and append if validation passes
      --bundle <BUNDLE>...           Bundle additional files for project-level reification (compiled languages)
      --project-root <PROJECT_ROOT>  Project root for bundled reification (auto-detected if not specified)
      --fast                         Fast mode: <5s local iteration, deferred validation (default)
      --full                         Full mode: full semantic guarantees (30-90s)
      --interactive                  Interactive guided mode (recommended for beginners)
      --try-branch <TRY_BRANCH>      If set, the proposal is associated with an ephemeral try branch
      --breaking                     Gap 2: Mark as breaking change
      --issue <REF>                  Gap 2: Link to related issue/PR (can be specified multiple times)
      --test-note <NOTE>             Gap 2: Test coverage note (e.g. "added test_pricing.rs")
      --tag <TAG>                    Gap 2: Metadata tags (can be specified multiple times)
      --push [<REMOTE>]              Gap 4: Auto-push after solidify (optional remote name, defaults to origin)
      --amend                        Amend the existing proposal: load and modify the candidate stash
      --compact                      Compact output mode for agent-friendly token usage (Strategy 6)
      --persona <PERSONA>            Persona: developer (default), user, agent. Also supports NOOL_PERSONA env var
  -h, --help                         Print help
